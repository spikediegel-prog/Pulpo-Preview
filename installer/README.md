# Pulpo Preview graphical UEFI installer

Status: **live ISO build exists (scripts + docs in this PR). Boot-test
results live in `BOOT-TEST.md` — read that file, not this line,
before claiming the ISO boots.**

## What this is

The graphic installer for Pulpo Preview, built on the work that
already exists instead of starting over:

- The wizard steps are the Control Center's Guided Setup (PR #55):
  Welcome, Time servers, Timezone, Network, Storage, Summary.
  Same order, same questions, same validation.
- The config it writes is the Control Center customer config,
  schema `pulpo.control-center-customer-config.v1` — the exact
  document `pulpo-control-center config import` accepts, so the
  installer and the installed system agree on what "configured"
  means. No second config format, no second authority plane.
- The images are the UEFI set made first for this installer
  (`assets/`): boot splash, installer welcome, installing
  progress, square boot logo. Pulpo Preview **0.1.0** — the
  welcome/progress mockups carry invented version strings that
  are not used here.

## What is in this folder

- `assets/` — the installer images, including the boot splash as
  PNG and as `pulpo-uefi-boot-splash.bmp` (1920x1080, 24-bit BMP,
  the format GRUB/UEFI graphics mode reads). The PNG stays the
  source of truth.
- `grub.cfg` — the live ISO's GRUB menu, generated by
  `make_live_grub_cfg.py` from the Ubuntu 24.04.5.1 base ISO's
  menu. Live-only: Try live / safe graphics / Check media. There
  is deliberately NO "Install" entry — no disk installer exists
  yet, and the menu must not offer one.
- `installer-manifest.json` — every installer image, its role,
  size, and SHA-256, so a build can verify nothing was swapped.
- `validate_config.py` — validates a config document against the
  guided-setup rules (NTP, timezone, DHCP/static, gateway on
  subnet, DNS max 3, retention max 24h, storage acknowledgement).
  Run: `python3 validate_config.py pulpo-preview-config.example.json`
- `pulpo-preview-config.example.json` — a valid example config
  (DHCP, America/Phoenix, Ubuntu NTP + pool, local evidence store).
- `build-iso.sh` — the live ISO builder (rootless remaster of the
  Ubuntu 24.04.5.1 desktop ISO; see its header for the verified
  base-ISO facts). Run: `installer/build-iso.sh`
- `make_live_grub_cfg.py` — turns the base ISO's GRUB config into
  the live menu above. The kernel lines stay the base's, verbatim.
- `boot-test.sh` — boots the built ISO under QEMU + OVMF (TCG, no
  KVM) and captures a serial boot log + screenshots.
- `BOOT-TEST.md` — how the ISO was boot-tested, and what the test
  does and does not prove. The results table in that file is the
  boot claim; nothing here repeats it.
- The clickable wizard itself is the "Pulpo Preview Graphic
  Installer" space in the Library — same steps, same rules, and it
  exports the finished config as a downloadable JSON file.

## How the live ISO is built (short version)

Rootless, because the build VM has no sudo and no unprivileged user
namespaces: ISO tooling (xorriso, QEMU, OVMF) is fetched as Ubuntu
`.deb`s and extracted with `dpkg-deb -x` into a prefix; the live
rootfs is the base ISO's top squashfs layer
(`casper/minimal.standard.live.squashfs`), unpacked with
`unsquashfs`, customised by copying files in, repacked with
`mksquashfs`; the ISO is rebuilt with xorriso replaying the base
image's boot chain verbatim. The Control Center goes in from its
existing `.deb` (preview.47); `pulpo` from this repo via
`pip install --target`; `python3-tk` from its `.deb`s (it is not in
the base image). First boot autologs into GNOME and autostarts the
Control Center. Boot-test note (2026-11-11, QEMU + OVMF): under
QEMU's `qemu64` CPU the Qt interface dies with `Illegal
instruction (core dumped)` — the vendored Qt needs AVX, which
`qemu64` lacks — while the Tkinter Control Center opens and runs.
See BOOT-TEST.md. Full details: the header of `build-iso.sh`.

## Rules the installer must not break

- **Gateway is a security control, not just a network setting.**
  DHCP by default. An unset gateway (no default route, no internet
  access) is a valid, deliberate choice — the installer says so
  plainly and never nudges the admin toward "connect to internet".
- **Pulpo governs and reports, that's it.** The installer writes
  config and installs the system. It does not grant authority,
  create permits, or touch the Pulpo kernel. First boot hands off
  to the Control Center's Guided Setup apply path
  (`config import --apply-network` via pkexec); the installer
  never runs as root itself and never stores credentials.
- **Storage honesty:** local evidence is kept at most 24h, and
  Pulpo is NOT responsible for the customer's data, backups, or
  storage. The admin must acknowledge that warning to continue.

## What is NOT done yet (honest gaps)

- Nothing here has booted on real hardware. The Protectli Vault
  Pro VP6630 is the target; a boot test there is the gate before
  any "it installs" claim. The QEMU boot test (see BOOT-TEST.md)
  is done: the ISO boots under UEFI firmware, reaches the GNOME
  desktop, and the Tkinter Control Center runs — but the GRUB menu
  + splash screenshot was not captured (the 5s menu fell between
  shots), and the Qt Control Center needs real hardware to be
  checked (it SIGILLs under QEMU's `qemu64` CPU).
- Secure Boot: the live ISO reuses Ubuntu's signed shim/grub
  unchanged, so it boots under Secure Boot via Microsoft's key.
  That has NOT been demonstrated under Secure Boot enforcement
  (the QEMU run uses plain OVMF, Secure Boot off) — it is a
  separate, still outstanding check. Pulpo's own key / MOK
  enrolment is still an open decision. No Pulpo key has been
  generated, enrolled, or used for signing.
- No disk partitioning step exists yet — the wizard collects the
  storage *choice* (external/local, path, retention); the
  partitioner (Calamares or a guided Qt disk step) is still open.
  The ISO is live-only.
