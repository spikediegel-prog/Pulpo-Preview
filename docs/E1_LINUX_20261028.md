## Failure and smallest change

The Linux listener parser accepted invalid states, queues and nonnumeric local
endpoints. The diagnostic CLI replaced existing reports and followed symlinks.
Reject malformed enumeration before constructing a report. Publish complete
diagnostic JSON from a private temporary file using create-only hard linking,
file sync and Linux directory sync. Existing paths, including dangling symlinks,
are never replaced. Creation failures return 2 without success stdout. Directory
sync failure retains the report but returns 2: durability is unknown.

The report schema is unchanged. Use a fresh filename for each invocation of
`python -m scripts.check_network_exposure --evidence /private/path/new-report.json`.
Use an operator-owned directory with private access. Hard-link-incompatible
filesystems fail; NAS/SAN durability and hostile parent-directory replacement
are not established. An existing reader or interrupted run must not be mistaken
for a fresh successful collection. Exit 0 means the exact supplied allowlist
matches enumeration; 1 means unexpected listeners; 2 means collection/publication
error. Empty allowlist remains the default. No host listener is auto-approved.

## Validation and limits

Ubuntu targeted suite: 41 tests, including the 8 new diagnostic tests, listener
proof, transport policy, guarded recovery and crash-harness oracle checks.
Control Center: 17 tests, 16 passed and one graphical test skipped. These are
source tests, not packaged lifecycle or visible GUI validation. A separate
disposable process-crash harness passed 21 crashes, 9 SQLite storage failures
and 3 tamper controls per backend (baseline and candidate). Retain its JSON and
logs with the run evidence. It proves bounded SIGKILL,
SQLite error and tamper cases, not machine power loss or live-service recovery.
The first harness attempt failed before its first crash because its dynamically
loaded baseline module omitted __package__ and child processes use -W error.
The one-line loader fix declares the existing pulpo package; a strict subprocess
regression test covers it. The original failed report is retained separately.
The runtime host scan uses no allowlist and is expected to reject SSH and other
host listeners; it is diagnostic evidence, not an admission pass.

New tests cover malformed rows; numeric IPv6/scopes/wildcards; 0600 publication;
regular-file/symlink/dangling-link collisions; ENOSPC at file sync; unsupported
link publication; directory sync uncertainty; and suppressed success stdout.
Targeted evidence does not establish production readiness or full E1 completion.

## Adversarial transformation record

- Flip: hostile or drifting enumeration cannot silently become valid proof.
- Reverse: reject malformed rows before report construction and file linking.
- Invert: a passing listener report with failed persistence returns an error.
- Inside-Out: treat diagnostic output and its storage as fallible observations.
- Darken: full disk, unsupported storage and symlink collisions fail visibly.
- Lighten: benign format drift or duplicate filenames can cause rejection.
- Amplify: repeated publication cannot overwrite earlier reports; unique names
  can still exhaust disk, so automatic retention remains a separate design.
- Negate: reuse the existing listener diagnostic without privileged remediation
  or a second governance/evidence plane.

Continue only within disposable development tests. No merge, push, publication,
production operation or live-state rotation is part of this slice. Legacy source:
existing listener parser/CLI and recovery harness only; no legacy control path
copied. Temporal boundary: the exact parent source is a relevant regression
checkpoint; the new cases characterize its missing checks. No whole-system
historical-transfer or reusable organizational-learning proof is claimed.
