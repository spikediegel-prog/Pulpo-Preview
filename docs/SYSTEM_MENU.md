# System menu categories

System shows every available option under four visible category headings:

| Category | Options |
| --- | --- |
| System health | System status, Export sources, Troubleshooting |
| Setup & storage | Setup guide, Storage & saved setup |
| Appearance | Appearance |
| Performance | Performance settings, Benchmark tools |

There is no category-selection step or hidden second row. Selecting an option
highlights it and shows a short explanation of its purpose. Buttons wrap into
fewer columns for narrow windows and larger fonts. Ctrl+K uses the same visible
names and accepts storage terms including NAS, SMB, NFS, SAN and retention;
previous search words continue to work.

Existing internal view keys, saved startup views and deep links are unchanged.
Storage & saved setup remains the existing Session setup page. The storage plan
still records intent and acknowledgment only; menu navigation enables no export,
benchmark, repair, settings save or governance capability.

## Change record

1. Invariant/failure: users could not find storage under Remember setup; the old
   two-level menu hid destinations behind an extra category selection.
2. Authority delta: none; visible links select existing views only.
3. Canonical mutations: none. No kernel, writer, router, ledger or credential
   surface is introduced; existing explicit action boundaries remain in each view.
4. Evidence: navigation tests check every destination stays mapped, exact target
   selection, selected-state uniqueness and no owner reads/preferences saves.
   Existing larger-font/reflow, lifecycle, storage and preference tests remain.
   Search tests cover visible names, storage aliases and old search words.
5. Limits: widget tests do not establish visible VM acceptance, live source
   availability, production enforcement or storage durability. No automatic update
   or deployment is introduced by this change.
6. Classification: Proposed usability improvement; Recorded local test results
   accompany the PR. Production/customer usability remains Unknown until observed.
7. Reuse: existing System views, selection callbacks, style tokens, reflow function
   and session preference schema; no legacy control path copied.
8. Temporal transfer: current UI-only change; no reusable governance lesson or
   applicable historical authority-transfer claim.

Analytical passes: Flip—hostile navigation has only fixed existing view targets;
Reverse—no path from a menu selection to a new write capability; Invert—visible
pages do not prove setup success; Inside-Out—UI remains an observer; Darken—small
windows must wrap, with page scrolling preserved; Lighten—labels and grouping
alone address discovery; Amplify—repeated visits do not accumulate authority or
state; Negate—remove the extra category-selection mechanism instead of adding
new setup automation. Review grants no authority.
