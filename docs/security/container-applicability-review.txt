These prerequisite summaries are Recorded source information, not proof of
absence or applicability in Preview. A missing direct Python reference alone
cannot prove a native dependency never executes vulnerable code.

The new read-only probe records exact installed package file lists/versions,
named component paths, hashes, SUID/SGID/file capabilities, Perl module loading,
and the bounded process security context. It does not dump environment values
or production credentials. It runs with the image's non-root user, no network,
read-only root, no capabilities and no-new-privileges. A privileged or incomplete
probe context fails before subprocess collection. Image identity is preserved
with the report. No canonical Pulpo state or external provider is accessed.

Eight-pass review: Flip — hostile evidence remains untrusted, not an approval.
Reverse — require exact image/component evidence before disposition.
Invert — a package/version label or passing probe does not clear a CVE.
Inside-Out — collector has no production credential or canonical writer.
Darken — vulnerable native paths may exist below Python imports; remain blocked
where evidence is incomplete. Lighten — package-source matching may cover code
not present in a binary package; prove that before calling it unaffected.
Amplify — collect all four images and reject elevated/missing security context.
Negate — remove unused infocmp and SUID/SGID helper privileges at image build,
then verify with an isolated read-only probe. Continue: narrow image capabilities
and collect evidence without executing exploit payloads or changing scan policy.

Proposed image hardening: remove /usr/bin/infocmp and strip SUID/SGID on regular
files in the image filesystem. Keep runtime libraries, package records and
non-root service entrypoints. This narrows OS helper capabilities; introduces
no canonical state mutation, credential, authority route or production access.
The strict image probe rejects a remaining infocmp or SUID/SGID file under
/usr, /bin or /sbin, as well as root/capable/missing no-new-privileges contexts.
Build success and service regressions must be checked at the published tree.
